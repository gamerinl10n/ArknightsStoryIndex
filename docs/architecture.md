# 개발 기준과 다음 단계

한국어·중국어·일본어·영어 대사와 문맥을 제공하는 공개 검색 도구입니다. A만 선택하면 말투 조사, A→B는 이름·등록 별칭이 포함된 대사 조사입니다. 호칭과 지칭 대상의 판단은 사용자에게 맡기며 관리자 검토·인증·외부 검토 저장소는 사용하지 않습니다.

## 데이터 경로

공개 원본 저장소 → SHA 고정 체크아웃 → 원문 스냅샷 → 자체 파서 → SQLite 검색 DB → Flask 화면/API.

수집·가공은 sync.py/build.py에서 실행합니다. Vercel은 generated/search.sqlite.gz를 /tmp의 임시 캐시에 한 번 풀어 읽기 전용으로 엽니다. 요청 중 원본 수집이나 영구 데이터 쓰기는 하지 않습니다. 로컬 아카이브와 배포용 검색 DB를 분리하고 원본의 영구 백업은 별도로 운영해야 합니다. 구버전 DB의 검토 테이블은 삭제하지 않지만 검색·배포에서는 완전히 무시합니다.

## 의미와 정확도

인물의 동시 등장은 발화 상대의 근거가 아닙니다. 대상 검색은 이름·사전에 등록된 표기가 본문에 포함된 후보를 반환합니다. 직접 호칭이나 제삼자 지칭이라는 확정 표시는 하지 않습니다. 앞뒤 대사와 분기 표기를 제공하고 서로 다른 분기의 물리적 인접 대사를 같은 대화로 간주하지 않습니다. 다른 언어의 같은 줄 위치 후보는 UI에서 제거했습니다. 기존 API 필드는 호환성을 위해 남겨두지만 대응을 보증하지 않습니다.

원본 db6f9ef8046ad17dbebe3ff1d0dd88844a5bc78c의 한국어·일본어·영어 각 353,998개, 중국어 371,403개 대사(총 1,433,397개)를 적재했습니다. M3→켈시 이름 포함 후보는 한국어 50개·중국어 45개·일본어 45개·영어 43개입니다. 이 수치는 확정된 호칭 수가 아닙니다. Mon3tr의 검색 약칭 M3를 명시적으로 등록했습니다.

## 후속 우선순위

1. 내레이션·자막·선택지·다중행 문법과 개발용 문서 분류, 파서 누락 진단.
2. 인물의 언어별 표기·별칭 사전 확장과 정체 공개 범위 처리.
3. 파일 존재 여부 대신 공개 메타데이터로 선행 스토리 필터 구성.
4. 문맥 확장과 분기 그래프, 다국어 대응 개선.
5. 원본 직접 다운로드 어댑터와 실패·삭제 검사. 완성 전에는 수집 경로 독립성을 주장하지 않음.
6. 삭제 스토리 처리, 갱신 상태 및 백업 복원 시험.


## 검색 UI와 공통 크롬

자동완성은 검색창에 연결된 combobox/listbox이며 /api/suggestions에서 현재 언어·공개 범위에 존재하는 화자를 반환하며, 공식 ID로 확인한 다른 언어 이름과 등록 약칭은 표시하지 않는 검색 키로 함께 제공합니다. 자동완성을 불러오지 못하면 직접 입력도 가능합니다. 사용 설명서와 로딩·빈 결과·오류 상태를 제공합니다.

base.html이 공통 헤더·푸터를 소유하며 안내 문서는 pages.py의 서비스별 사실을 렌더링합니다. theme.js는 CSS보다 먼저 저장된 테마를 복원하고 chrome.js가 버튼·접근성 레이블·탭 간 저장소 이벤트를 처리합니다. 테마 아이콘과 관련 CSS는 L10ndiff에서 요청에 따라 가져왔습니다. 검색어는 localStorage에 저장하지 않습니다. 개인정보 안내는 서버 검색·URL 로그 가능성을 명시합니다.

공식 캐릭터 ID로 언어별 이름을 연결합니다. /api/context는 요청당 앞뒤 최대 100개 대사로 제한하며 분기 표기를 보존합니다. 화면 언어 선택은 대사 언어도 함께 바꾸며, 검색창에서 대사 언어만 별도로 고를 수 있습니다. 공유 주소에 검색 조건을 기록합니다. 업데이트 알림은 L10ndiff의 update-monitor.mjs와 동일한 감지·재알림 로직을 사용합니다.

검색 첫 화면은 중앙 검색창, /search는 결과의 직접 진입 주소입니다. 같은 폼을 공유하고 History API로 조건을 복원합니다. 지원 브라우저는 View Transitions API, 그 외에는 짧은 CSS 전환을 사용하며 reduced-motion에서는 이동 애니메이션을 생략합니다.

사용 방법은 네 언어로 서버 렌더링한 네이티브 dialog에 포함합니다. /help 이전 링크는 /?help=1로 연결합니다. 대사·문맥의 상세 모달에 원본 파일·행·분기·버전을 보존합니다. API의 story 조건은 원본 path의 정확 일치이며, 파일별 개수도 호환성을 위해 유지합니다. 화면에서는 스토리 드롭다운과 복사 버튼을 제공하지 않습니다. 원본 파일명을 공식 이벤트 제목으로 추정하지 않습니다.

푸터 링크 이름은 현재 화면 언어 하나로 표시합니다. 개인정보·이용안내·라이선스·패치 노트 본문은 한국어와 영어를 같은 문서에 병기하고 해당 문서에서는 화면 언어 전환을 표시하지 않습니다. 검색 및 사용 방법 모달의 네 언어 지원은 유지합니다.

## 성능 구조

검색 SQL은 search_queries.py, 이름 사전은 catalog.py, DB 연결·자동완성은 search_service.py로 분리합니다. 빌드에서 공개 범위별 화자 수를 집계하며 변경 가능한 아카이브는 캐시하지 않습니다. 첫 결과는 대사만 조회하고 문맥·대응 후보는 사용자가 펼칠 때 요청합니다. 프런트엔드 ui/ 모듈은 전역 상태 대신 명시적인 import와 함수 인자를 공유합니다. API 캐시는 탭 메모리에 한정하고, 버전별 정적 파일만 장기 캐시합니다. 세부 검증과 벤치마크는 development.md를 참고하세요.

단어만 입력하면 화자 제한 없이 본문을 검색합니다. 파일별 집계를 재사용해 해당 페이지에 기여하는 파일만 재조회합니다. 초상화는 공식 ID와 고정 원본 SHA로 빌드한 96px WebP이며 서버의 로컬 이미지 인덱스를 사용합니다. 이름 충돌·원본 누락은 기본 아이콘으로 표시합니다.

검색 폼은 DOM 순서로 단어 → 화자 → 대상 → 검색 → 대사 언어 → 인물 바꾸기 → 선행 스토리를 탐색합니다. 양수 tabindex나 Tab 이벤트 가로채기는 사용하지 않습니다. 화면 배치는 CSS Grid로 유지하며 corpus-control.mjs가 네이티브 선택값과 접근성 있는 언어 목록을 연결합니다.

## 가까운 상대 발화와 문맥 묶기

두 인물 검색은 같은 분기에서 가까운 상대 발화가 있는 일치를 우선합니다. 발화자가 교대한다는 사실만으로 호칭이나 1대1 대화를 확정하지 않습니다. 다른 화자·분기 경계에서는 인접 발화 탐색을 멈추며, 원문에 대상 이름이 없는 대사를 새 일치 결과로 추가하지 않습니다.

한 페이지에서 같은 파일·분기의 일치가 원본 6행 안에 있으면 모든 일치 대사를 한 카드에 유지하고 문맥 펼치기를 공유합니다. 다른 파일·분기·페이지 사이에는 묶지 않습니다. 서버의 전체 개수와 페이지 오프셋은 카드 수가 아닌 일치 대사 수입니다.

## 구조를 검증한 원문·번역 대조

translation_alignment.py가 빌드 중 원본 아카이브를 읽어 비번역 명령 속성·분기·명령 순서와 텍스트 수, 알려진 화자 ID를 검증합니다. 검증을 통과한 파일의 실제 ordinal 쌍을 압축하여 translation_alignments에 저장합니다. 물리 행 번호가 같다는 이유만으로 연결하지 않으며 댓글·빈 줄로 원본 행이 달라도 연결할 수 있습니다. 파일별 원본 해시와 양쪽 revision, 알고리즘 버전을 보존합니다. 구조가 다른 파일은 연결하지 않습니다.

API의 compare=1과 translation_lang=ko_KR/ja_JP/en_US는 선택 사항입니다. 중국어에서 검색하면 선택 번역을, 번역에서 검색하면 중국어를 붙입니다. 원래 검색 결과·정렬·개수·공개 범위는 유지하고 일치한 페이지나 펼친 문맥에만 대응을 일괄 조회합니다. 단일 언어 검색은 추가 대응 조회를 하지 않습니다. 기본 legacy parallel 필드는 예전 같은 행 위치 후보의 API 호환용으로 남지만 새 대조 UI는 사용하지 않습니다.

UI는 원문·번역 대조 체크 시 중국어 검색을 기본으로 설정하고 번역 언어를 선택하게 합니다. 번역에서 역방향 검색도 가능합니다. URL과 언어 전환·뒤로 가기·입력 지우기에 모드 및 번역 언어를 보존합니다. 번역 파일 없음과 구조 대응 미확인을 구분하며 기계 번역으로 채우지 않습니다. 의미상 대응을 보증하는 수치는 표시하지 않습니다.


## 통합 다국어 검색 (2026-10-23)

UI는 all_languages=1을 보내고 lang은 페이지 언어로 고정합니다. multilingual_search.py는 네 언어의 literal 일치를 파일 순서로 스트리밍하고, 현재 파일의 검증된 ordinal map과 revision만 사용해 페이지 언어 또는 중국어 원문으로 정규화합니다. 임시 테이블의 복합 키로 중복을 제거한 다음 가까운 상대 발화 순위·파일·행으로 정렬하고 50개씩 반환합니다. 전체 일치를 Python 메모리에 보관하거나 원문 아카이브를 읽지 않습니다. 대응을 검증하지 못한 행은 합치지 않습니다. 이름만 검색할 때는 기존 페이지 언어 검색 경로를 유지합니다. 기존 API 기본 동작과 compare 파라미터는 호환용으로 남습니다.

보이는 페이지의 variants만 일괄 조회합니다. 검색은 표시 언어 선택과 무관하므로 선택을 바꿔도 결과 수·페이지·열린 문맥을 유지합니다. 다른 언어 대사 DOM은 기본 숨김이며 결과 버튼은 해당 속성만 바꿉니다. 문맥은 여전히 열 때만 요청하고 all_languages=1에서만 대응을 붙입니다. URL의 show에 추가 표시 언어를 보존합니다. 페이지 언어는 항상 표시하며 검증된 대응이 없으면 검색된 언어와 안내를 보입니다. 이전 독립 검색 언어 선택과 대조 모드 UI는 제거했습니다.


## 검색 결과의 연속성

검색 식별자는 인물·단어·대표 언어·공개 범위·다국어 모드만 포함합니다. 표시 언어 변경은 결과를 무효화하지 않습니다. result-state.mjs는 탭의 한정된 메모리에 최근 결과 노드와 읽던 상태를 보관하며, History API 복귀 후 View Transition 적용 시점에 스크롤을 복원합니다. 데이터/페이지 버전 변경은 새 문서를 열어 보관 상태를 초기화합니다. 문맥은 계속 지연 조회하며, 분리된 카드에서 진행된 응답은 화면 복귀 시 연결합니다.

다국어 검색의 후보 처리는 파일 단위로 묶습니다. 대표 언어에서만 일치한 파일은 후보 정규화용 맵을 읽지 않고, 다른 언어 일치가 있으면 필요한 언어 쌍만 압축 해제합니다. 파일 내 고유 대응만 임시 테이블에 일괄 삽입하고, 기존 순위·중복 제거·페이지 순서를 유지합니다.


## 이름 일치 표시

검색 API는 대상 인물이 있을 때 catalog.aliases와 같은 언어별 이름 목록을 highlights에 제공합니다. UI의 highlight.mjs가 대사 검색어와 해당 언어 이름의 literal 구간을 모아 겹친 부분을 나누어 렌더링합니다. innerHTML이나 정규식 보간을 쓰지 않고 원문 textContent를 보존합니다. 결과 카드가 가진 이름 목록을 문맥에도 재사용하므로 추가 서버 요청은 없습니다. 이 표시는 이름 일치일 뿐, 화자나 청자 관계를 확정하지 않습니다.
