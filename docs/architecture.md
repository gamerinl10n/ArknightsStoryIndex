# 개발 기준과 다음 단계

합의: 한국어·중국어, 한국 서버 공개분 기본, 선행 스토리 선택, 공개 검색/단일 관리자 검토. A만 선택하면 말투 조사, A→B는 호칭·지칭 근거 조사.

## 저장 계층

공개 원본 저장소 → SHA 고정 체크아웃 → 원문 스냅샷 → 자체 파서 → SQLite 대사 → 검토 오버레이. 검토 이력은 원문 교체와 별도이다. API는 요청마다 DB 연결을 열며 원본 반영은 트랜잭션 단위이다.

현재 원본 줄 번호가 식별자라 삽입/삭제 시 검토가 자동 재연결되지 않는다. 해시 불일치 기록은 확정 근거로 쓰지 않는다. 향후 내용 해시·주변 문맥으로 재연결 후보를 만들되 관리자 확인 없이 이동하지 않는다.

## 후속 우선순위

1. 실제 원본으로 파서 커버리지 보고서와 누락 진단 작성. 인물 사전에는 언어별 표기, 별칭, 정체 공개 범위를 포함.
2. M3→켈시 용례를 수동 검증하고 직접 호칭/지칭/오탐 회귀 데이터로 확보.
3. 파일 존재 여부 대신 이벤트 공개 메타데이터로 스포일러 범위 결정.
4. 줄 ID 대조를 대체할 다국어 대응 검증. 선택지 분기 그래프 및 맥락 표시 개선.
5. arkprts 버전을 고정한 직접 다운로드 어댑터를 별도 작업 디렉터리에서 시험. 최소 한국어 파일 수, 파싱 실패율, 급격한 삭제 검사를 통과한 스냅샷만 반영. 자동 전환 전 수동 검증.
6. 단일 관리자 로그인 방식, 배포 플랫폼, 영구 저장소 확정 후 공개 운영. 현재 토큰 방식은 개발용 운영 경로.
7. 인물별 색인/페이지 성능 측정, 갱신 상태 기록, 백업 복원 시험, 정기 실행 추가.

직접 다운로드가 준비되기 전에는 수집 경로 독립성이 완성되었다고 표현하지 않는다. 기존 원본 저장소가 중단되어도 마지막 저장본 검색은 가능하나 새 콘텐츠 수집은 멈춘다.

## 2026-10-22 실데이터 검증

원본 SHA `db6f9ef8046ad17dbebe3ff1d0dd88844a5bc78c`에서 초기 파서로 한국어 353,998개, 중국어 371,403개 대사를 적재했다. 한국어 M3→켈시 이름 포함 검색은 50개, 중국어 동일 검색은 한국어 스토리 파일 존재 범위에서 45개 후보를 반환했다. 이는 자동 후보 수이며 검토 완료 호칭 수가 아니다. 실제 화자 표기는 Mon3tr이므로 M3 검색 약칭을 명시적으로 연결했다.

일반 텍스트 줄도 많이 존재하며 설명 파일이 섞여 있으므로 전체 파서 완전성을 주장하지 않는다. 내레이션/선택지/자막과 개발용 문서 분류가 다음 파서 작업이다. 파일 수·미처리 텍스트 수 보고를 추가했고, 성공 상태만 DB에 기록한다. 전체 대사 수의 20% 이상 감소(기존 100개 이상)는 반영 전에 차단한다.


## Vercel 실행 경로

Flask app.py → 읽기 전용 generated/search.sqlite → 선택적인 PostgreSQL 검토 오버레이. 수집·가공은 build.py에서만 실행하고 요청에서는 실행하지 않는다. 원본/스냅샷과 검색 DB를 분리해 런타임 크기를 줄인다. PostgreSQL 검토 이력은 원본·검색 DB 재생성과 독립적이다. 별도 DB가 연결되지 않은 배포는 검색 전용이다.

로컬 app.py CLI와 공개 API는 같은 create_app을 사용한다. 로컬 원본 DB는 contextlib.closing으로 요청 후 연결을 닫는다. Serverless에서는 schema DDL이나 파일 생성을 하지 않고 SQLite mode=ro, immutable=1로 연다. 검토 오버레이는 요청 연결에만 존재하는 TEMP 테이블이며 다른 요청과 공유하지 않는다. PostgreSQL 실패 시 검색 결과에 검토가 없는 것으로 오인시키지 않도록 503을 반환한다.

검토 저장소는 단일 운영자 규모를 가정해 요청마다 전체 검토 오버레이를 조회한다. 검토량이 커지면 언어·화자/대상별로 분할해야 한다. 관리자 OAuth와 데이터 직접 다운로드 경로, 원본 영구 아카이브 운영은 여전히 후속 작업이다.
