# 다음 개발 목록

기본 검색 기능을 기준으로 후보를 모으고, 사용자와 범위를 확정한 묶음 단위로 구현·검증·배포합니다. 아래 후보는 아직 구현 승인을 받지 않았습니다. 작은 변경은 공개 패치노트에 기록하지 않습니다.

## 확정한 변경

- 헤더 순서: 화면 언어 → 다크·라이트 모드 → 사용 방법(?). 시각 순서와 키보드 순서를 함께 변경.

## 다음 묶음 후보

| 우선순위 | 항목 | 구현 전 확인 및 완료 기준 |
| --- | --- | --- |
| 1 | 모바일·키보드 실제 브라우저 회귀 검증 | 좁은 화면, 네 언어, 밝고 어두운 테마에서 긴 입력 안내·자동완성·모달·고정 푸터를 확인. 검색 → 문맥 → 홈 → 뒤로 가기까지 자동 검증하고 가로 넘침·초점 문제를 수정. 현재 CI의 jsdom 테스트와 별도로 검증. |
| 1 | 검색 결과 복귀 상태 보존 | 홈이나 브라우저 뒤로 가기로 돌아왔을 때 검색 조건뿐 아니라 스크롤·펼친 문맥·추가로 불러온 결과를 복원. 메모리 보관량을 제한하고 새 검색·언어 변경·버전 변경 시 오래된 결과를 사용하지 않음. |
| 1 | 인물 검색의 본문 강조 | 현재 일반 문구(q) 강조를 대상 인물의 실제 일치 이름·등록 별칭에도 적용. 원문을 유지하고 겹친 일치·유니코드·다국어 별칭을 검증. 직접 호칭이나 청자라고 확정하는 표시는 하지 않음. |
| 2 | 단어 단독 검색 성능 측정과 개선 | 현재 벤치마크는 두 인물·한 인물 중심. 네 언어에서 짧은 단어·흔한 단어·일치 없음·다음 페이지를 측정한 뒤 병목을 개선. 현재 부분 문자열 검색 의미와 결과·개수를 유지. 인덱스 추가는 배포 DB 용량 예산을 함께 검증한 뒤 선택. |
| 2 | 데이터 갱신 확인·검증 자동화 | 현재 고정 원본 및 수동/변경 기반 빌드는 유지. 새 원본 감지 → 수집·누락/감소 검사 → 갱신 PR 준비를 자동화하는 방안. 변경은 검증된 배포로 반영하고 실패 시 기존 데이터를 유지. 사용자 검색 기록을 수집하지 않음. |

권장 첫 묶음은 1순위 세 항목입니다. 성능 작업은 측정 결과를 토대로 별도 범위를 확정합니다. 원천 다운로드 어댑터·분기 그래프는 장기 과제로 architecture.md에서 관리합니다.
