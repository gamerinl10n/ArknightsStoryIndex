# Project rules

Read README.md and docs/architecture.md before changes. Preserve Korean/Chinese text and provenance. Never infer addressees from co-occurrence alone or label name matches as confirmed forms of address. Let users judge using context. Do not add administrator review, login, review records, or external review-storage dependencies. Never present synthetic dialogue as official. Never commit secrets, raw game dumps, or runtime databases. Run unit tests and JavaScript syntax checks. Ship changes via a feature branch and PR; report missing live-data verification explicitly.
